# State Interpreter研究方法与复用原则

## 核心原则

当实验效果不好时，默认动作不是立刻自行增加模型复杂度或继续调参，而是先判断已有论文和成熟开源实现是否已经处理过同类问题。

```text
发现失败
→ 定位失败类型
→ 检索论文与官方/高质量开源实现
→ 复现成熟基线
→ 在相同数据划分和指标下比较
→ 只对仍未解决的部分做最小创新
```

## 失败后的固定检查顺序

1. **确认失败是什么**：表示无健康信息、时间建模不足、跨工况偏移、阶段假设错误，还是评价泄漏。
2. **检索对应方法族**：优先论文官方代码，其次维护良好的学术工具库，再次是协议透明的工程基准。
3. **核查可比性**：数据集、任务、标签、输入形式、划分和指标是否与当前项目一致。
4. **建立成熟基线**：尽量保持作者方法，不在首次复现时混入自行修改。
5. **统一评价**：使用bearing级LOBO、多随机种子、训练集专用归一化及预注册门槛。
6. **再做改进**：只有成熟基线仍暴露明确缺口时，才提出自己的模块，并做一次只改变一个因素的消融实验。

## 代码来源优先级

1. 同行评审论文的官方仓库；
2. 有测试、文档、许可证和固定评价协议的研究库；
3. 数据集专用且结果可复现的工程基准；
4. 第三方论文复现；
5. 无论文、无测试或只提供notebook的个人实现。

GitHub stars只能作为维护活跃度的弱参考，不能代替论文证据和本项目复现。

## 采用方法的最低记录要求

每个候选必须记录：论文与代码链接、官方性、许可证、输入、输出、训练目标、时序机制、跨域机制、标签需求、原始数据集、评价协议、与当前接口的适配点，以及不能直接迁移的部分。

## 当前项目的具体执行顺序

1. 复现XJTU-SY成熟基准中的65维特征、onset detection和Feature LSTM；
2. 若两阶段强基线仍不足，复现TS2Vec作为上下文化Encoder；
3. 健康表示成立后，再使用rul-adapt/AdaTime中的DANN或MMD处理跨工况偏移；
4. HMM/HSMM仅用于组织可靠的阶段观测；Attention仅在基线证明长程依赖不足时引入；
5. Bearing3_5在最终方案锁定前保持未读。

## 停止条件

- 不因单个bearing失败就连续追加模块；
- 不在同一验证bearing上反复选模型；
- 不因模型更复杂就默认更先进；
- 不把RUL、分类或异常检测仓库的输出直接称为RL state；
- 不复制整个仓库后再寻找研究问题，而应先明确要复现的组件与假设。
